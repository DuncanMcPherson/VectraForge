# Contributing to VectraForge

Thank you for your interest in contributing to VectraForge. This document covers how to get involved.

## Getting Started

1. Fork the repository on GitLab.
2. Clone your fork and create a branch from `master`.
3. Make your changes, keeping commits focused and descriptive.
4. Open a merge request against `master` with a clear description of what you changed and why.

## Development Setup

- .NET 10 SDK is required.
- Build with `dotnet build` and run with `dotnet run --project VectraForge`.
- The project uses Avalonia UI — familiarity with MVVM and AXAML is helpful.

## Guidelines

- Keep changes scoped. One concern per merge request.
- Match the existing code style. Consistency matters more than personal preference.
- If you're adding a significant feature, open an issue first to discuss the approach before writing code.
- Bug fixes should include a description of the failure mode and how the fix addresses it.

## Reporting Issues

Open an issue on the [GitLab issue tracker](https://gitlab.com/vectra-lang/vectra-forge/-/issues). Include steps to reproduce, expected behavior, and actual behavior. Attach relevant logs or screenshots if applicable.

## Code of Conduct

Be respectful. Disagreement on technical grounds is fine; personal attacks are not.
